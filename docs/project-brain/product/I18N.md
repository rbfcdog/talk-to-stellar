# I18N.md — Internationalization System

> **Living document.** Updated when i18n bugs are found or new surfaces are added to the audit.

## How It Works

The i18n system resolves language from user profile settings. Supported locales: `pt-BR` (default), `en-US`.

**Resolution chain** (should be):
```
recipient's profile.config.language
  → fallback: pt-BR
```

## The Recipient-Locale Bug Class (Pain Point #10)

**Problem**: User with EN config receives PT messages because the SENDER's locale is used for recipient-facing text.

> "se a minha config ta em inglês, faça TUDO meu ser em inglês" (#10)

**The Rule**:
```
EVERY user-facing text must resolve locale from the RECIPIENT's config.
NOT the sender's. NOT the session's. NOT the server's default.
```

## Language Toggle Placement

> "nao eh pra ter o botão de ingles no meio dessa tela de conversão, so no coisinho do canto direito superior" (#24)

**Rule**: Language toggle belongs ONLY in the app chrome (header/settings). Never inside a transactional flow screen.

## Implementation
