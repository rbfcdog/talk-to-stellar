# UX review e ajustes prioritarios

Data: 2026-05-28.

## O que mudou nesta iteracao

1. Aplicacao agora mostra como opcao principal apenas moedas com vault DeFindex configurado.
2. BRL/TESOURO fica fora da lista de aplicacao enquanto nao existir `DEFINDEX_TESOURO_VAULT`.
3. Saldos sem vault aparecem como "outros saldos" e devem ir para conversao antes de investir.
4. A tela de aplicacao ganhou botao curto para `Converter ativos`.
5. A tela PIX de saida, quando falta saldo, mostra caminhos de recuperacao:
   - abrir conversao de ativos;
   - usar outro saldo disponivel na propria retirada.
6. O guia do chat foi encurtado para uma resposta rapida com poucos exemplos.

## DeFindex: confirmacao da documentacao

Fonte oficial consultada: https://docs.defindex.io/api-integration-guide/smart-contracts

A pagina confirma dois caminhos de integracao:

1. SDKs: caminho mais rapido para integrar carteira.
2. Smart contracts: mais controle, mais complexidade.

Para usuario final, os metodos relevantes sao:

- `deposit`
- `withdraw`
- `balance`

Metodos como `invest`, `unwind`, `harvest`, `rebalance`, `rescue`, `set_fees`, `pause`, `unpause` e mudancas de manager sao operacionais/admin/keeper. Portanto, a UX de usuario nao deve chamar `invest` diretamente como se fosse acao da pessoa. O botao "Investir" da interface deve preparar um `deposit` no vault; a alocacao em estrategias fica no lado do vault/gestor.

## Regra de produto para aplicacao

Moedas aplicaveis sao somente as que voltam de:

```text
GET /api/ramp/defindex/yield/status
```

Esse endpoint deve refletir apenas envs `DEFINDEX_<ASSET>_VAULT` configurados para a rede ativa.

Para o testnet atual:

```env
DEFINDEX_USDC_VAULT=CBMVK2JK6NTOT2O4HNQAIQFJY232BHKGLIMXDVQVHIIZKDACXDFZDWHN
DEFINDEX_CETES_VAULT=CBIS5TEMTNNOTBE3WXPQUAGUEDYZZVIWAKTXEQCOUJ34OJJ3FJ5NLF2P
DEFINDEX_XLM_VAULT=CCLV4H7WTLJQ7ATLHBBQV2WW3OINF3FOY5XZ7VPHZO7NH3D2ZS4GFSF6
```

Como nao ha `DEFINDEX_TESOURO_VAULT`, BRL/TESOURO nao deve aparecer como opcao de aplicacao.

## Melhorias de UX ainda recomendadas

1. Unificar os botoes de recuperacao quando falta saldo: `Converter ativos`, `Adicionar por PIX`, `Usar outro saldo`.
2. Mostrar uma linha simples em conversao: "Testnet: valores estimados podem variar".
3. Na tela de PIX saida, quando a pessoa pede BRL mas so tem USDC/CETES/XLM, sugerir automaticamente o maior saldo disponivel.
4. Criar teste Playwright para:
   - `/review` com BRL sem vault;
   - `/review` com USDC/CETES/XLM;
   - `/pix-off` com saldo insuficiente;
   - `/pix-off` usando outro saldo.
5. Manter os docs e a interface alinhados para mostrar XLM como XLM.

## Criterio de pronto

1. BRL nao aparece como aplicacao sem `DEFINDEX_TESOURO_VAULT`.
2. USDC, CETES e XLM aparecem se os respectivos vaults estiverem configurados.
3. A pessoa sempre tem um caminho claro quando falta saldo: converter, adicionar ou usar outro ativo.
4. Chat responde curto e nao manda catalogo longo.
5. Interface principal nao usa termos tecnicos como vault, issuer, trustline ou XDR.
