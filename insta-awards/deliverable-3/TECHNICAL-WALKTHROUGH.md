## 1. TransferOrchestrator — The Heart of the System

**File**: `backend/src/orchestration/TransferOrchestrator.ts` (625 lines)

### Overview

`TransferOrchestrator` is the only class that performs state transitions on the normalized `transfers` table. It:
- Validates transitions against the state machine before executing
- Calls atomic PostgreSQL RPCs for state changes
- Records append-only `transfer_events` rows
- Emits structured JSON log lines per transition
- Handles idempotent replay for duplicate evidence

### transition (line 423)

The core method that ALL state changes flow through:

```typescript
private async transition(
  transfer: Transfer,
  toState: TransferState,
  eventType: TransferEventType,
  updates: Partial<Transfer>,
  payload: Record<string, unknown>,
  actor: TransferActor,
  correlationId?: string | null,
): Promise<Transfer> {
  // 1. Validate transition is legal
  TransferStateMachine.assertTransition(transfer.state, toState);

  // 2. Atomic RPC: update transfers row + insert transfer_events row
  const updated = await transferRepository.transition({
    transferId: transfer.id,
    expectedVersion: transfer.state_version,   // ← optimistic lock
    toState,
    eventType,
    payload,
    actor,
    correlationId,
    updates: { ...updates, state: toState },
  });

  // 3. Emit structured log
  this.log(updated, eventType, transfer.state, toState, actor, ...);

  return updated;
}
```

### assertTransition (line 46)

}

### checkTransfer (line 64)

```typescript
private async checkTransfer(transfer: Transfer): Promise<void> {
  const txHash = String(stellar.submitted_tx_hash || stellar.tx_hash || '').trim();
  const exhausted = elapsedMs > this.config.intervalMs * this.config.maxAttempts;

  if (!txHash) {
    if (exhausted) {
      await orchestrator.fail(transfer.id,
        'Stellar watcher exhausted without a submitted transaction hash.',
        'poller:stellar');
    }
    return;
  }

  const confirmation = await checkHorizonTx(txHash, this.config.horizonUrl);
  if (confirmation) {
    // Transition: CONVERTING → STELLAR_SETTLED
    await orchestrator.confirmStellarSettlement(transfer.id, {
      tx_hash: txHash,
      ledger: confirmation.ledger,
      network: 'testnet',
      settled_at: confirmation.settledAt,
      source_account_masked: 'stellar:***xxxx',
      asset: 'USDC',
      path_used: ['BRL', 'USDC'],
    }, 'poller:stellar');
  } else if (exhausted) {
    await orchestrator.fail(transfer.id,
      `Stellar watcher exhausted before Horizon confirmed tx ${txHash}.`,
      'poller:stellar');
  }
}
```

### checkHorizonTx (line 99)

```typescript
export async function checkHorizonTx(
  txHash: string,
  horizonUrl: string,
): Promise<{ ledger: number; settledAt: string } | null> {
  const res = await fetch(`${horizonUrl}/transactions/${encodeURIComponent(txHash)}`);
  if (!res.ok) return null;  // not found or still pending
  const tx = await res.json();
  if (tx.successful) {
    return {
      ledger: Number(tx.ledger || 0),
      settledAt: String(tx.created_at || new Date().toISOString()),
    };
  }
  return null;  // transaction exists but failed
}
```

**Key behaviors**:
- Only queries `CONVERTING` transfers (not all transfers)
- Requires `stellar.submitted_tx_hash` to be set before polling begins
- Has a time window (`intervalMs * maxAttempts` = ~10 minutes default)
- On exhaustion: transitions to `FAILED`
- On confirmation: transitions to `STELLAR_SETTLED` and attaches ledger + settled_at

## 6. How Reconciliation Works

### Automatic Reconciliation

`TransferOrchestrator.computeReconciliation()` at line 470 is called in two places:

1. **After Stellar settlement** (`confirmStellarSettlement`, line 230): Pre-computes reconciliation when settlement evidence is available but payout hasn't happened yet. Discrepancies at this stage are expected (`missing_payout_routing_status`, `missing_same_name_check`).

2. **After payout instruction** (`instructPayout`, line 266): Re-computes reconciliation with full payout evidence. At this point, all expected fields should be present.

### Manual Reconciliation

`TransferOrchestrator.markReconciled()` at line 279 is the "finalize" method. It:
1. Loads the current transfer
2. Validates the transition to `RECONCILED` is legal
3. Computes or accepts a reconciliation payload
4. **Refuses** to reconcile if `amounts_match === false` or `discrepancies.length > 0`
5. Sets `reconciled_at` and `reconciled_by`
